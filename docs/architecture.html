Architecture Reference

Factory Inventory Management System

An analytics dashboard for factory operations: a Vue 3 single-page app talking to a FastAPI service that serves fixture data held in memory. No database, no authentication, no persistence — every process restart returns the system to its initial state.

System Architecture

Two processes, started independently, communicating over plain HTTP on localhost. The frontend holds no build-time knowledge of the backend beyond a hardcoded base URL; the backend holds no knowledge of the frontend at all and permits any origin.

Consequence of the in-memory design: mock_data.py reads every JSON file once at import time into plain Python lists. Handlers filter those lists with list comprehensions on each request. Data Flow

Every page follows the same path. The example below traces a user narrowing the dashboard to a single warehouse — the interaction that exercises the most layers.

  1. Filter changes in the UI
    components/FilterBar.vue

    Four <select> controls — Time Period, Location, Category, Order Status — are bound with v-model to refs owned by the filter composable.

  2. Shared state updates
    composables/useFilters.js

    The refs are declared at module scope, outside the exported function. Every importer receives the same ref instances, so the composable acts as a singleton store — this is what replaces Pinia in this codebase.

  3. Views react and request
    views/*.vue

    Each view watches the filter refs and calls getCurrentFilters(), which maps UI names onto API names — selectedLocation becomes warehouse, selectedPeriod becomes month.

  4. Query string assembled
    api.js

    Any filter whose value is the sentinel 'all' is omitted from the URLSearchParams. An absent parameter therefore means "unfiltered" — the client and server agree on this convention independently, in two places.

  5. Server filters the lists
    main.py — apply_filters, filter_by_month

    Filters apply sequentially over the in-memory lists. Category and status match case-insensitively; warehouse matches exactly. Month accepts either 2025-03 or a quarter key such as Q1-2025, expanded through QUARTER_MAP.

  6. Aggregation, where it happens server-side
    /api/dashboard/summary, /api/reports/*

    Three endpoints compute rather than return: inventory value, low-stock counts and pending orders for the dashboard; per-quarter revenue and fulfilment rate; and month-over-month trends. Everything else returns filtered rows unchanged.

  7. Pydantic validates the response
    response_model=List[…]

    Applied on the six list endpoints. The aggregate and spending endpoints return bare dicts with no model, so their shape is unchecked.

  8. View stores raw, derives computed
    views/*.vue

    Response arrays land in ref()s untouched. Every displayed number — KPI cards, chart series, status tallies — is a computed() over those refs, so a new response recalculates the page automatically.

Cross-cutting: localisation and currency

useI18n.js uses the same module-scope singleton pattern, backed by localStorage. Locale drives currency: en renders USD, ja renders JPY through utils/currency.js, which multiplies by a hardcoded rate of 150. The API is currency-agnostic and always returns USD figures — conversion is purely a presentation concern.

Observations

Points where the code does not match its stated intent. Each was verified against the running system rather than inferred from reading alone.

Broken

The task feature has no server

App.vue calls api.getTasks() on mount and offers add, delete and toggle. None of the four /api/tasks routes exist. Every call 404s, and the handler swallows the failure into console.error, so the Tasks modal silently falls back to the four hardcoded tasks in useAuth.js. The UI gives no indication that anything failed.

Broken

Purchase orders can never be created

purchase_orders.json is an empty array, and the only code that would write to it is the unimplemented POST /api/purchase-orders. The has_purchase_order flag that /api/backlog computes is therefore false for every item, permanently. The two client methods for this feature are dead code — nothing calls them.

Unreachable

Backlog.vue is orphaned

The view is fully written and fetches its own data, but main.js registers no route for it and the nav bar has no entry. The README advertises backlog monitoring as a feature. The Dashboard shows backlog data inline instead, via BacklogDetailModal.

Data

Fulfilment rate declines across quarters by construction

/api/reports/quarterly defines fulfilment as delivered ÷ total orders. Later-quarter orders are more likely to still be Shipped or Processing, so the metric falls from 77.4% in Q1 to 35.5% in Q4 — an artefact of order age, not of performance. It sits alongside a 96.8% "order fill rate" on the Overview page, computed differently.

Config

Permissive CORS

allow_origins=["*"] is combined with allow_credentials=True. Acceptable for a local demo, and the server's own CLAUDE.md flags it — worth noting because the combination is rejected by browsers in a deployed setting.

Coupling

Filter conventions are duplicated

The 'all' sentinel is stripped client-side in api.js and independently checked server-side in apply_filters. Both must stay in agreement, but neither references the other. The same is true of the UI-name to API-name mapping.
